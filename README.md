# ORBITA Assistant 1.3

Локальный помощник для подготовки сообщений покупателям Авито. На главной — четыре входа в сценарии; отдельная библиотека содержит 118 исходных ответов ORBITA. В сценариях доставки и самовывоза выбирайте текущую ситуацию напрямую: этапы не блокируют друг друга, а копирование не требует служебных отметок. Приложение не подключается к Авито и ничего не отправляет: копирование только кладёт подготовленный текст в буфер обмена.

Холодная цветовая система, контрастные состояния и мобильные/desktop скриншоты собраны в [отчёте по палитре 1.3](docs/color-system-1.3.md).

## Разработка

- Требуется Node.js 24.
- `npm ci` — установить зависимости.
- `npm run dev` — запустить Vite для разработки.
- `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build`, `npm run audit:public`, `npm run audit:budget` — проверки.
- `npm run test:e2e` — сценарии Playwright в Chromium; перед запуском установите браузер командой `npx playwright install chromium`.
- `CI=1 npm run test:e2e` — Chromium плюс desktop Safari и iPhone Safari WebKit профили (CI выполняет это на GitHub-hosted runner).
- `npm run audit:lighthouse` — пересобрать проект, измерить Lighthouse mobile и записать результат в `docs/performance.md` (требует Chromium и доступа к npm для Lighthouse CLI 13.5.0).

Сборка использует `base: /orbita-assistant/` для GitHub Pages проекта `yarrobong/orbita-assistant`.

Локальные и публикационные критерии ORBITA Assistant 1.2 описаны в [docs/acceptance-1.2.md](docs/acceptance-1.2.md).

## Данные и безопасность

Избранное, недавние ID шаблонов и последняя выбранная ситуация хранятся только в этом браузере. Текст ответа, адрес и контакты остаются в памяти текущей вкладки и не входят в публичную сборку. Выбор фактической ситуации означает, что вы указываете на этот факт; если необходимых даты, времени или адреса нет, приложение покажет нейтральный ответ без незаполненных плейсхолдеров. До согласования выдачи текст не подтверждает встречу. Контакт человека на точке включается только после подтверждения разрешения и отдельного выбора. `npm run audit:public` проверяет шаблоны и собранные файлы на личные данные.

## Публикация

Push в `main` запускает workflow `CI`: он проверяет код, сборку, данные, Chromium/WebKit браузерные сценарии и Lighthouse, а затем публикует `dist/` в GitHub Pages. Для репозитория выберите `Settings → Pages → Build and deployment → GitHub Actions`.

## Обновление ответов и резервирование

Встроенные ответы обновляются в `src/data/templates.ts` на основе исходной базы ORBITA. После правок запускайте `npm run audit:public`, `npm run test` и `npm run test:e2e`, затем коммитьте изменения в `main`; CI опубликует новую версию после проверок. При доступной версии приложение предлагает обновление, которое активируется только после выбора пользователя.

MVP не создаёт пользовательские шаблоны и не хранит резервируемый пользовательский каталог. Избранное и последняя стадия сценария остаются в браузере и доступны только на этом устройстве; для сохранения встроенной базы используйте версию в Git. Очистка данных браузера удалит локальное избранное и историю последнего сценария.
